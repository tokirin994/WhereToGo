# TravelAtlas 免费试用部署指南

本文按 2026-10-21 可查到的免费层设计，目标是把当前 Vue 前端、Spring Boot API 和 PostGIS 数据库公开给少量试用者。免费额度和地区政策会调整；创建服务前请再次查看平台页面。本配置适合演示与个人试用，不提供生产级可用性、自动备份或数据恢复承诺。

## 本机启动（Windows）

本仓库后端使用 Java 8。需要安装 Java 8 JDK、Node.js 20.19+ 和 PostgreSQL 16/PostGIS；本机启动脚本不依赖 Docker。将 PostgreSQL 程序和数据放在 `D:\Application\PostgreSQL16`，Java 与 Maven 可使用 `D:\Application\Jdk-1.8` 和 `D:\Application\Apache-maven-3.9.11`。项目首次打包后，在仓库根目录运行：

```powershell
$env:JAVA_HOME = 'D:\Application\Jdk-1.8\jdk-1.8'
$env:PATH = "$env:JAVA_HOME\bin;D:\Application\Apache-maven-3.9.11\bin;$env:PATH"
Push-Location .\backend
mvn -DskipTests package
Pop-Location
Push-Location .\smartledger\backend
mvn -DskipTests package
Pop-Location
& .\scripts\start-local.ps1
```

脚本会启动本机数据库、SmartLedger API、两个前端和仅供本机演示的 OIDC 登录端点。访问 `http://localhost:5173` 打开 WhereToGo，访问 `http://localhost:5174` 打开 SmartLedger。SmartLedger 自动使用本地超管模拟身份（`admin@localhost`，无需密码）；它只模拟身份，不提供跨用户管理能力。此身份服务只绑定回环地址，不能用于公网或生产。日志保存在 `D:\Application\WhereToGo\logs`，PostgreSQL 数据保存在 `D:\Application\PostgreSQL16\data`。

## 推荐组合

| 服务 | 用途 | 免费层注意事项 |
| --- | --- | --- |
| Cloudflare Pages | 发布 `frontend/` 静态文件 | 支持 GitHub 自动构建；免费层每月最多 500 次构建，单次构建最长 20 分钟。 |
| Render Web Service | 以 Docker 运行 Spring Boot API | 免费实例 15 分钟无请求后休眠，唤醒通常约一分钟；文件系统临时；免费实例可能重启。 |
| Supabase Postgres | 持久化 API 数据并启用 PostGIS | 免费数据库 500 MB；低活跃项目可能在 7 天后暂停；免费层没有自动备份。 |

参考：[Cloudflare Pages 免费限制](https://developers.cloudflare.com/pages/platform/limits/)、[Render 免费服务限制](https://render.com/docs/free)、[Supabase 免费额度](https://supabase.com/pricing)、[Supabase PostGIS](https://supabase.com/docs/guides/database/extensions/postgis)。

## 1. 准备数据库

1. 在 Supabase 创建 Free 项目，并选择离 API 服务较近的区域。
2. 在 **Database → Extensions** 中启用 `postgis`。项目迁移包含 `CREATE EXTENSION IF NOT EXISTS postgis`；先启用可避免数据库角色没有创建扩展权限。
3. 从 **Connect** 页面复制数据库连接信息。保存主机、端口、数据库名、用户名和密码。应用通过后端连接数据库，绝不要把数据库连接串放进前端变量。
4. 备份好密码。首次启动 API 时，Flyway 会自动运行仓库内的迁移并建立表结构。

## 2. 部署后端 API

1. 在 Render 选择 **New → Web Service**，连接 `tokirin994/WhereToGo` 仓库，分支选择 `master`。
2. Runtime 选择 **Docker**，Root Directory 填 `backend`，Dockerfile 使用 `backend/Dockerfile`（在 Root Directory 下即 `Dockerfile`）。镜像会在构建阶段通过 Maven Wrapper 编译，再以 Java 8 运行。
3. 设置 Health Check Path 为 `/api/v1/health`。
4. 添加环境变量：

   | 变量 | 值 |
   | --- | --- |
   | `SPRING_DATASOURCE_URL` | `jdbc:postgresql://<supabase-host>:5432/postgres?sslmode=require`；如果 Supabase 为你提供连接池 URI，按其主机、端口和数据库名替换。 |
   | `SPRING_DATASOURCE_USERNAME` | Supabase 提供的数据库用户名。 |
   | `SPRING_DATASOURCE_PASSWORD` | Supabase 数据库密码。 |
   | `APP_CORS_ALLOWED_ORIGINS` | Cloudflare Pages 的生产站点源，例如 `https://your-project.pages.dev`，不要在末尾加路径。 |

   Render 会通过 `PORT` 变量分配监听端口，应用已配置为读取该值。
5. 等待部署完成，然后打开 `https://<render-service>.onrender.com/api/v1/health`。首次请求可能遇到免费实例唤醒延迟。

## 3. 部署前端

1. 在 Cloudflare Pages 创建 **Workers & Pages → Create → Pages → Connect to Git**，选择同一仓库。
2. 设置 Production branch 为 `master`，Root directory 为 `frontend`，Build command 为 `npm ci && npm run build`，Build output directory 为 `dist`。
3. 在 Pages 项目的 **Settings → Environment variables** 中，为 Production 添加：

   | 变量 | 值 |
   | --- | --- |
   | `VITE_API_BASE_URL` | Render API 的完整源，例如 `https://your-api.onrender.com`，不要在末尾加斜杠。 |

4. 触发部署并打开 Pages 提供的 `*.pages.dev` 地址。前端构建时会把 API 源写入静态资源；变更该变量后需要重新部署。
5. 如果绑定了自定义前端域名，把后端 `APP_CORS_ALLOWED_ORIGINS` 改为该域名的源，并重新部署 API。允许多个来源时使用逗号分隔的明确域名，不要使用 `*`。

## 4. 部署后检查

- 打开 `/api/v1/health`，确认返回健康状态。
- 在前端创建一个测试地点，刷新页面后确认仍存在；尝试编辑、删除并确认数据变化。
- 检查浏览器 Network 面板：API 请求应发往 Render 源，且没有 CORS 错误。
- 检查 Render 日志中的 Flyway 迁移结果；不要把数据库密码或供应商密钥贴入 issue、截图或前端环境变量。
- 免费 Render 服务休眠后，第一条 API 请求会慢；不要用定时 ping 绕过休眠限制。
- Supabase Free 项目可能在低活跃一周后暂停，且没有自动备份。需要保留重要数据时，定期从 Postgres 导出 SQL/自定义格式备份到本地安全位置，并先验证备份可恢复。

## 当前边界与后续升级

- 目前没有登录与多用户隔离，API 使用仓库内固定的本地演示用户。上线地址只能供可信的个人演示使用，不能放入敏感地点或开放给不可信用户。
- 目前没有图片上传、文件存储、AI 密钥配置、链接导入、路线和天气 API；本部署不需要这些密钥。
- 需要稳定响应或真实用户数据时，为 API 和数据库配置付费实例、备份与监控，并先完成登录授权、用户数据隔离、密钥管理和限流。免费服务不应承载有可用性要求的生产数据。
