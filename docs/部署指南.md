# WhereToGo 部署指南

更新：2026-10-25。门户、旅行、独立记账、统一账号和数据库的完整公网部署，使用 [免费部署操作手册](免费部署操作手册.md)。该手册包含平台注册、DNS、两套 Pages、Oracle 当前免费额度、密钥生成、生产 Compose、备份与恢复、更新及验收步骤。

## 推荐公网组合

Cloudflare Pages 托管两个前端，OCI A1 免费 VM 承载两个 Java 8 API、Keycloak 和 PostgreSQL/PostGIS。当前 Oracle 免费 A1 为合计 2 OCPU / 12GB，注册和创建前以官方政策与控制台为准。Render/Supabase 的休眠、额度共享和备份边界已在操作手册说明；不再把只部署单个旅行 API 的旧步骤当作完整系统方案。

不要将本机的 HTTP 登录、Vite 开发服务器、数据库端口直接开放公网。安全与账号细节见 [安全与 API 管理](安全与API管理.md)、[统一账号与凭证加密](统一账号与凭证加密.md)。

## 本机启动（Windows）

后端使用 Java 8，依赖 Node.js 24、PostgreSQL 16/PostGIS。本机启动脚本不依赖 Docker；软件放在 `D:\Application` 对应应用目录。Keycloak 单独使用它需要的 Java 运行时，不将两套业务后端改为高版本 Java。

首次打包后运行：

```powershell
$env:JAVA_HOME = 'D:\Application\Jdk-1.8\jdk-1.8'
$env:PATH = "$env:JAVA_HOME\bin;D:\Application\Apache-maven-3.9.11\bin;$env:PATH"
Push-Location .\backend
mvn -DskipTests package
Pop-Location
Push-Location .\smartledger\backend
mvn -DskipTests package
Pop-Location
& .\scripts\start-local.ps1
```

尚未安装本地身份服务时，先运行 `scripts/install-identity.ps1`。启动脚本启动数据库、两个 API、两个前端和回环 Keycloak，并关闭前端 mock 登录：

| 服务 | 本机地址 |
| --- | --- |
| 公开门户 | `http://localhost:5173/` |
| 旅行 | `http://localhost:5173/travel/` |
| 独立记账 | `http://localhost:5174/` |
| 账号中心 | `http://localhost:5173/account/` |
| 旅行健康状态 | `http://localhost:8080/api/v1/health` |
| 记账健康状态 | `http://localhost:8090/actuator/health` |

初始本地用户名为 `admin`；用 `scripts/show-initial-account.ps1` 在自己的终端查看随机密码，首次登录要求修改。数据库、日志和密钥仍在 `D:\Application` 下。开发配置与数据不应随代码推送到 GitHub。

## 当前已有外部能力

旅行已加入地点名称搜索、天气、路线、导航跳转、携带查询参数的预订平台跳转，以及多协议 AI 服务适配。外部 AI 需配置真实供应商与 key；免费公共搜索／天气／路线服务需遵守各自规则。详见 [旅行接入与验收](旅游服务接入与分期验收.md)。这些配置不是一律免费的保证。

本项目目前没有对全部账本实现端到端加密。坚果云凭证已用应用密钥加密，生产备份脚本另外用 age 公钥加密完整归档；具体保护范围和恢复要求见最新操作手册。
