# 移动端菜单与布局检查

## 问题与修复

- 应用切换菜单原来使用 `right: 0` 对齐触发器。触发器位于手机顶部中间时，264px 的菜单会跨过屏幕左边界。
- 记账顶部标题与四个操作按钮强制挤在同一行，导致“个人空间”等文字断行。现在标题和按钮组能整体换行，触摸按钮至少 44px。
- 旅游全局 `body` 曾设置 360px 最小宽度，在更窄的可视区域会溢出。现在支持 320px。

共享定位实现位于 `packages/platform/src/popover.ts`：

1. 按触发器和菜单的实际尺寸计算位置，将左右边缘限制在可视区域内。
2. 下方不足时优先向上展开；内容超过可用高度时在菜单内部滚动。
3. 监听页面滚动、窗口尺寸、`visualViewport` 和内容尺寸变化，重新定位。
4. 保留原生 details 键盘开关、Escape 关闭、点击外部关闭与焦点恢复。
5. 使用绝对定位保留所在应用的主题变量，不依赖 Safari 尚未普遍支持的 CSS 锚点定位。

已接入记账应用切换、账本/流水操作、分类操作，门户应用切换和账号菜单，以及旅游的行程、分享导出、智能编排、日程、合集操作菜单。

## 自动检查

单元测试包含左右边界、上下翻转、超长内容、可视区域偏移，以及 320/375/390/430/768/1280px 宽度。

移动 WebKit 回归脚本：

```sh
node scripts/test-webkit-sso.mjs --mobile --responsive --bundle-dir <production-dist>
```

`--bundle-dir` 可选；不传时检查已部署站点。需要通过环境变量提供：

- `WTG_PUBLIC_ORIGIN`：目标 HTTPS 站点。
- `WTG_USERNAME`、`WTG_PASSWORD`：专用测试账号。
- `WTG_PLAYWRIGHT_MODULE`、`PLAYWRIGHT_BROWSERS_PATH`：已安装的 Playwright 模块与浏览器位置。
- `WTG_BROWSER_REPORT_DIR`：忽略 Git 的本地报告目录，例如 `.local/mobile-layout-report`。

检查范围包括：

- 320×740、390×844、430×932、768×1024、1280×900、844×390 的记账布局。
- 菜单所有边界、最后一个应用可达、菜单打开期间调整屏幕宽度、Escape 和点击外部关闭。
- 日历、账本排序、账本列表与详情的多级导出菜单、流水、识图、分类管理。
- 浅色与夜间模式、记账编辑中的嵌套分类选择弹窗。
- 门户账号菜单、旅游菜单和窄屏内容布局。
- 原有 SSO 回归：门户一次登录、记账刷新、阻止 iframe 后的新标签恢复、返回导航和统一退出。

脚本使用隔离浏览器上下文。旅游行程和合集测试记录通过浏览器请求拦截返回，禁止写入服务器。主题和记账草稿只保存在该测试浏览器内；不会操作真实账号账目。

这是 WebKit 引擎测试，不代表实际 iPhone Safari 硬件测试。仍应在真机检查浏览器地址栏收起、软键盘、系统大字体和双指缩放时的显示。
