# SmartLedger 抵扣规则与验收

更新日期：2026-10-25。规则依据为本次用户确认的五项要求，以及 `W:/SmartLedger/client/ios/SmartLedger` 中的原 App 源码。日期跟随和移出账本的范围采用用户指定的网页规则。

## 已实现的操作

| 用户要求 | 实现行为 |
| --- | --- |
| 抵扣参考 App | 已有抵扣和本次新增分开管理。已有抵扣按稳定 ID 保存，可以逐笔展开、修改实际金额／收入分类／日期、单独删除；新增抵扣采用比例，不覆盖已有流水。 |
| 日期默认按照原支出 | 首次创建默认跟随关联支出；调整原支出时间时，跟随模式的抵扣一起更新。再次编辑原支出并追加抵扣，默认当前时间、独立日期。手动修改抵扣时间会切换为独立日期，也可以勾选恢复跟随。 |
| 关闭清空全部抵扣 | 先弹出明细，列出所有已保存抵扣的分类、金额、日期和本次待新增项。确认后暂存清空状态，点击“保存流水”才实际删除所有关联抵扣；取消清空或放弃编辑会保留原记录。 |
| 移出账本保留网页行为 | 从某账本移除原支出时，同步移出其全部关联抵扣及该账本的分摊设置；不全局删除流水，其他账本归属保留。确认信息明确列出关联抵扣数量。 |
| 超过 100% 参考 App | 每笔新增比例允许 0–200%；累计已有和新增抵扣超过支出时，可以返回修改、仍按原比例创建，或仅调整新增抵扣至剩余额度。 |

### 金额与归属

- 修改原支出金额不重算已收到的抵扣。例如原支出 100、已有抵扣 30 和 20，改为支出 200 后仍为 30 和 20。
- 原支出的标题、备注、商户、渠道、账本归属、付款人和参与者信息会同步到全部关联收入；保留各笔收入的实际金额、收入分类以及独立日期。
- 已有抵扣 50 元、新增按 60% 和 30% 抵扣 100 元支出时，选择调整只将新增分配为 33.33 和 16.67 元，已有 50 元保持不变。使用整数分和余数分配避免尾差。
- 如果已有抵扣本身已超过支出，不减少已有实际收入；选择调整时，新增额度为零，不生成零金额流水。已有总额依然可能超过 100%，弹窗会说明这一点。
- 新建分期订单首次抵扣按照订单总额计算；后续对某期追加抵扣，按照当前这一期金额计算，与 App 的追加入口一致。
- 取消分期后，关联抵扣迁移到合并后的支出；跟随模式调整到新关联支出日期，独立日期保留。提前还清和全局删除仍清理其对应支出的关联抵扣。
- OCR 保持 App 的单笔初始抵扣入口和 0–100% 范围。OCR 入账后，可以通过普通流水编辑追加多笔抵扣。

### 日期存储与兼容

流水新增可选字段 `offsetDateMode`：`source`（跟随支出）或 `independent`（独立日期）。该字段和关联 ID 一起进入本地快照与完整快照同步，仍使用快照版本 4，不需要数据库迁移。

旧快照没有日期模式时：与原支出时间戳一致的推断为跟随，时间不同的推断为独立，保留历史报销日期。无法凭旧数据推断“特地设成同一个时间”的意图，这种情况可在编辑器主动取消跟随。旧 `source=offset:<id>|...` 关联格式仍可读取。

首次分期抵扣的跟随对象是其关联的首期支出。后续追加默认独立日期；手动选择跟随后，跟随所关联的那一期。

### 保存保护

- 确认超过 100% 期间，只在独立工作副本计算，不将半成品放入可同步的当前账本。
- 如果打开编辑器后原记录／关联抵扣被更新，或确认期间完整快照变化，拒绝旧编辑覆盖，提示重新打开核对。
- 本地保存失败恢复原流水及支付渠道；从账本移除失败恢复原支出与所有抵扣的账本归属。

## 手工检查路径

1. 打开本地记账服务，编辑支出，启用“抵扣与报销”；默认新增一笔 100% 抵扣，分类选择器保持折叠。
2. 保存后重新编辑同一支出，追加抵扣；检查默认时间是当前时间且“日期跟随原支出”未勾选。
3. 修改原支出时间，检查已有跟随抵扣随动，后续追加和手动修改过时间的抵扣保持独立；修改支出金额不改变已有收入。
4. 关闭抵扣，检查明细包含全部抵扣；点保留不变，确认全部清空后取消编辑也不删除，最终保存才清空。
5. 支出 100 元、已有抵扣 50 元，新增 80%：确认时分别尝试取消、保留比例、调整新增，结果应为不保存、合计 130 元、合计 100 元。
6. 从一个账本移除支出，检查该账本不再包含其抵扣，全部流水和其他关联账本仍保留这些记录。
7. 浅色、深色和跟随系统模式分别查看折叠卡片、分类弹窗、清空明细与超过 100% 弹窗。

修复前的原始核查保留在 [历史核查](./SmartLedger抵扣联动核查.md)，其中旧差异说明不代表本次实现后的状态。
