# Git 隐私审查与提交规则

## 本次远程审查

2026-10-28 执行 `git fetch --all --prune` 后，检查了远程主分支、Dependabot 分支及其可达历史。检查时共 26 个远程分支、33 个提交、580 个不同 blob，约 18 MB；另外存在 origin/HEAD 符号引用，没有标签。数字是整改前快照，后续提交会增加数量。

检查范围包括代码、配置、文档、样例，以及历史提交的文件对象。检查私钥格式、常见服务商 Key、JWT、URL 内嵌密码、个人邮箱、个人用户目录、IP 派生域名和疑似硬编码凭据，并人工核对疑似凭据用途。另使用本机受保护 SSH 凭据做精确比对，结果不回显凭据。

### 发现与处理

| 类别 | 结果与处理 |
| --- | --- |
| 可用密码、SSH 私钥、服务商 Key、真实 JWT | 在本次可达文本历史及已知 SSH 密码比对中未发现匹配；不能据此证明任意格式密钥都不存在 |
| 疑似凭据赋值 | 核对为测试假值、从私有 secret 文件取值、SQL 参数和显示受保护凭据的本机运维脚本，没有把这些匹配当成真实泄漏 |
| 实际部署域名 / 服务器地址 | 代码及文档确实包含；当前版本改为运行参数和示例地址，旧提交中的值仍存在 |
| 提交作者邮箱 | 历史元数据中有个人邮箱；当前仓库后续提交使用 GitHub noreply 邮箱，旧提交元数据仍存在 |
| 二进制对象 | 3 个 OCR 运行资源：两份压缩语言包和一个 WASM；未发现提交的截图、数据库备份或凭据文件。未对二进制内部做通用秘密识别 |

真实部署地址是基础设施信息，不等同于授权凭据。删掉当前文件中的地址**不会删除 Git 旧历史**。本次没有重写历史或强推：这会影响所有已有克隆及其他远程分支，需要先确认范围。若希望消除旧邮箱或部署地址，需要协调 Git 历史重写；GitHub PR、缓存、他人 fork 和已下载副本不在普通 Git 扫描或历史重写的控制范围内。

## 后续防护

- `.gitignore` 排除本机环境文件、DPAPI 凭据、私钥、数据库文件、加密备份、运行日志和 `.local` 审查结果。
- CI 对当前提交执行隐私扫描；高置信秘密和个人邮箱、IP 派生域名等规则命中时阻止流水线。通用凭据赋值只作人工审查候选，不直接断言为泄漏。
- 生产构建、线上验收、安装备份任务要求显式传入部署地址；不在脚本里保存实际地址。
- API Key 只在账号页面或服务器私有配置中设置；`VITE_*` 会进入浏览器构建产物，不能放秘密。
- 不把审查完整日志或真实部署参数重新写入公开文档。当前 Git 用户邮箱设置只作用于这个仓库，不改其他仓库身份。

## 重复检查

```powershell
# 提交前扫描跟踪文件及尚未忽略的新文件，不打印匹配值
python scripts/check-git-privacy.py --worktree --report .local/security-audit/worktree.json

# 远程检查；发现历史中已知基础设施信息会返回非零退出码
git fetch --all --prune
python scripts/check-git-privacy.py --history --report .local/security-audit/remote.json

# 检查某个提交及扫描器测试
python scripts/check-git-privacy.py --ref HEAD
python -m unittest discover -s scripts/tests -p test_git_privacy.py
```

规则扫描有局限，未接入第三方供应商在线 Key 验证，也不扫描 GitHub issues、Release 附件、fork、缓存、未获取的 PR 隐藏引用或本机被忽略的业务数据。若以后发现真实凭据，优先撤销或轮换，再处理 Git 历史；仅删文件不能使泄漏的凭据失效。
