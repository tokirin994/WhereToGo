# 旅游服务接入与分期验收

日期：2026-10-25。本记录覆盖本次新增能力；浏览器控制连接不可用，不能当作真实浏览器点击验收报告。

## 旅游服务

| 功能 | 当前实现与验证 | 边界 |
| --- | --- | --- |
| 名称搜索 | 默认接入 Photon，后端请求真实返回地点、地址、WGS84 坐标；选择后可保存 | 点击才查，不键入联想；缓存 15 分钟、单实例 1.1 秒间隔；不保证全部商户数据完整 |
| 天气 | Open-Meteo 城市候选、当前天气、未来最多 16 天预报；按旅行日期筛选，界面展示前 7 天 | 超过预报范围明确提示，天气不是远期确定事实；缓存 15 分钟 |
| 道路路线 | 当天 2–25 项已定位安排，支持步行／驾车道路几何、里程及耗时，绘制实线，按段展示 | 无实时路况、公交时刻与语音导航；未知位置不会跳过后伪装成完整路线 |
| 实时导航入口 | 将实际 WGS84 起终点、方式和允许范围内的途经点带到 Google Maps | 由外部地图负责当前位置、路况和导航；长路线不悄悄丢弃途经点，主入口不生成超过平台限制的链接 |
| 酒店 | Booking.com 搜索链接带住宿目的地、入住、退房、成人数；新窗口打开 | 成人数默认为同行人数，可编辑；儿童和房间在平台调整；本系统不代下单、不生成价格、房量和订单状态 |
| AI | 三种可切换协议；生成前仍需关联目的地收藏，输出使用同一所有权／日期／时间校验，先预览再应用 | 尚未选择真实供应商、模型和密钥，因此只做协议与业务校验测试，未调用付费模型 |

名称、天气与路线请求都经过现有认证接口；供应商地址由部署者固定配置，用户不能提交任意抓取 URL。超时、大小限制、不跟随重定向和有界缓存由 `ExternalJsonClient` 统一处理。供应商报错正文、密钥、令牌不返回前端或写业务日志。

默认公共服务适用于当前个人低流量使用；正式部署应按各供应商条款选择容量／商业许可。接口可通过对应空 URL 显式关闭。Photon 与 OSM 数据显示署名；路线保留服务说明及修正地图链接。

参考官方资料：[Photon](https://github.com/komoot/photon)、[Open-Meteo](https://open-meteo.com/en/docs)、[FOSSGIS 路线服务](https://routing.openstreetmap.de/about.html)、[Google Maps URLs](https://developers.google.com/maps/documentation/urls/get-started)、[Booking 接入方式](https://developers.booking.com/demand/docs/accommodations/accommodation-tutorial)。

## 通用 AI 配置

### 协议与供应商解耦

| 协议 | 服务端取值 | 常见适用配置 |
| --- | --- | --- |
| Chat Completions | `chat-completions` | DeepSeek、GLM、提供兼容协议的网关；GPT 兼容接口 |
| Responses | `responses` | OpenAI Responses 或支持此协议的网关 |
| Anthropic Messages | `anthropic` | Claude 原生接口；提供 Messages 协议的代理 |

不写死任何模型 ID，使用供应商账号当前可调用的模型名称。CC 若指 Claude Code，它本身不是统一可调用的服务端 API；应填写其背后网关的地址、模型与实际协议，不读取或复用桌面客户端的订阅／登录凭证。

可分别配置：基础地址、模型、密钥、协议、最大输出 token 数；兼容 `max_tokens`／`max_completion_tokens`；Claude 支持 `x-api-key` 或 Bearer，以及可配置版本头。地址可以为基础路径或完整协议端点，避免重复拼接。默认不传 temperature、工具定义和 JSON mode，减少不同推理模型对额外参数的拒绝。

三种响应只提取正式文本块，不把推理文本当作 JSON；空结果、截断结果、无效 JSON、不属于当前账号的地点和越界日期均失败，不改变原行程。不自动回退到另一个供应商，避免未经选择传输数据或额外计费。

参考：[OpenAI Chat Completions](https://developers.openai.com/api/reference/resources/chat/subresources/completions/methods/create)、[OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create)、[DeepSeek](https://api-docs.deepseek.com/api/create-chat-completion/)、[GLM](https://docs.bigmodel.cn/cn/api/introduction)、[Claude Messages](https://platform.claude.com/docs/en/api/messages/create)。

### Windows 本机加密配置

在项目根目录运行以下**格式示例**，替换模型 ID；脚本会隐藏输入 API Key，不需要把密钥写进命令历史或聊天：

```powershell
# DeepSeek：模型名由自己的账号决定
.\scripts\set-travel-ai.ps1 -Provider deepseek -Model '你的模型ID'
# GLM
.\scripts\set-travel-ai.ps1 -Provider glm -Model '你的模型ID'
# GPT / OpenAI：默认 Responses
.\scripts\set-travel-ai.ps1 -Provider openai -Model '你的模型ID'
# GPT Chat Completions 推理模型可显式改 token 字段
.\scripts\set-travel-ai.ps1 -Provider openai -Model '你的模型ID' -Protocol chat-completions -TokenField max_completion_tokens
# Claude
.\scripts\set-travel-ai.ps1 -Provider claude -Model '你的模型ID'
# 自己维护的 HTTPS 网关
.\scripts\set-travel-ai.ps1 -Provider custom -BaseUrl 'https://你的网关/v1' -Protocol chat-completions -Model '你的模型ID'
```

选择一种配置即可，重新运行会替换本机配置。文件位于 `D:\Application\WhereToGo\secrets\travel-ai.clixml`，密钥以当前 Windows 用户 DPAPI 加密保存，并限制文件访问；不是 Base64 混淆，不写入 Git、浏览器存储、旅游 JSON 或坚果云备份。Windows 账户／机器变化后应重新配置。

`start-local.ps1` 仅在启动旅游 API 时读取、解密并传给 Java 子进程，之后清理脚本环境中的临时明文密钥。**已运行的 API 不会热加载**，需要停止本项目旅游 API 后重新运行启动脚本；不能为此关闭无关 Java 服务。密钥在运行中的 Java 内存／进程环境必然可被本机有足够权限的用户读取，DPAPI 保护的是落盘配置。

正式云部署使用平台服务端秘密变量／Secret Manager，Windows DPAPI 文件不适合搬到 Linux。后端支持的 `TRAVEL_AI_*`、搜索、天气与路线环境变量见根 `.env.example`；供应商地址及模型必须匹配账号真实权限，GLM 编码套餐和普通 API 的端点／密钥不能混用。

## 记账分期与原 App 对照

依据为本机 `W:\SmartLedger\client\ios\SmartLedger\Core\LedgerStore.swift` 与创建流水页面。未重新运行远程模拟器，不能确认远程安装包与本机源码完全相同。

| 操作 | 原 App 规则 | 本次结论 |
| --- | --- | --- |
| 新订单分期 | 普通期先四舍五入到分，最后一期调尾差；独立起始日期；月底截断 | 核心及对照测试通过；100 / 3 为 33.33、33.33、33.34 |
| 普通流水拆为分期 | 保留首笔原 ID，生成同组多期；抵扣按原始总额 | 测试通过；手动 2–36 期、OCR 2–24 期 |
| 编辑已有一期 | 仅改当前一期，不暗中重拆整组或改总期数 | 测试通过 |
| 取消分期 | 合并整组**仍存在**的金额，使用代表流水 ID／最早日期，清空分期字段；迁移关联抵扣 | 测试通过；修复旧 `source=offset:<id>` 关联识别与迁移 |
| 删除订单／一期 | 删除选中流水及其生成的抵扣，其他分期继续保留 | 测试通过；不是删除整个分期组，网页确认文案已说明 |
| 提前还清 | 汇总严格晚于当前时刻的分期，在今天生成一笔还清流水；移除未来期及其关联抵扣，保留已到期记录 | 测试通过；与“取消分期合并整组”不同 |
| 防重复 | 同组已存在 `installment_payoff:<groupId>` 时拒绝再次还清；无未来期也拒绝 | 测试通过 |
| 保存失败 | 网页新增的取消／还清／删除不能让失败结果留在界面内存 | 从真实 Vue 函数提取执行，回滚测试通过 |
| 本地存储 | 分组、期号、总额、起始日期及还清 marker 不丢失 | JSON 规范化与隔离 IndexedDB 往返通过 |

旧关联兼容以 ID 已正确映射的网页版快照为前提，不意味着已经实现完整 iOS SwiftData／原生快照互导。极小金额可能产生非正末期时，网页会要求减少期数；这是原有的主动校验。其他非分期功能不在本次一致性结论中。
