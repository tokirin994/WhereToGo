# 服务器到本机的每日加密备份

## 已部署安排

| 项目 | 当前设置 |
| --- | --- |
| 服务器生成备份 | 每天香港时间 23:50（服务器 UTC 15:50） |
| 本机拉取 | 每天午夜 00:00，即所要求的 24:00 |
| Windows 任务 | `WhereToGo-EncryptedDatabaseBackup` |
| 本机备份目录 | `D:\Application\WhereToGo\backups` |
| 本机任务配置 | `D:\Application\WhereToGo\backup-sync\config.json` |
| 执行日志 | 同目录 `logs\日期.log` |
| 最近成功状态 | 同目录 `status.json` |

Windows 使用当前用户的交互登录凭据运行。电脑需要开机、联网并已登录；错过时间后通过可用性触发及登录触发补执行。不会依靠关机的电脑运行任务。已实际启动 Windows 计划任务并确认结果为 `0`（成功），并已下载、校验实际服务器备份。

备份是独立的加密归档文件，包含旅游、记账、账号三个数据库，以及恢复需要的服务器私有配置。原本机开发数据库继续独立存在；本任务只下载归档。

## 安全机制

- 服务器使用 `pg_dumpall` 生成 SQL，通过 age 公钥加密后才提供下载。临时 SQL 在完成加密后删除。
- 本机通过固定主机指纹的 SSH 连接，使用专门的 `wtgbackup` 只读账号；不使用 root 密码执行每日任务。
- 下载账号只允许 `list`、`stat 文件名` 和 `read 文件名`，文件必须匹配加密归档名称。禁止 shell、终端、端口转发、密码登录及读取其他文件。
- 下载前后校验大小及 SHA-256，写入 `.partial` 临时文件，通过校验才原子替换为完整归档。断线或校验失败不会留下伪装成完整备份的文件。
- 本机 SSH 私钥使用当前 Windows 用户的 DPAPI 加密，配置目录限制访问。专用 Python 依赖也在 D 盘目录内，后台任务不依赖终端的用户包路径。
- age 解密私钥保存在本机已有的 DPAPI 文件中，服务器只保留加密公钥。不要把解密私钥放回服务器或提交仓库。

当前不自动清理本机或服务器的历史归档，以免未确认异地副本就丢失备份。需要监控磁盘容量。备份 SQL 的一般业务字段在解密后可读，原数据库并未因此变成整库加密。

## 手动执行和查看状态

在项目根目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/run-backup-sync.ps1
Get-ScheduledTaskInfo -TaskName WhereToGo-EncryptedDatabaseBackup
Get-Content D:\Application\WhereToGo\backup-sync\status.json
```

也可以触发已安装的任务：

```powershell
Start-ScheduledTask -TaskName WhereToGo-EncryptedDatabaseBackup
```

`LastTaskResult=0` 表示最近一次任务成功；正在运行时可能显示 `267009`，需等其结束。失败时看日志；任务会按 10 分钟间隔重试，最多 3 次。备份文件超过 30 小时未更新时，本机报告错误，避免把旧备份误认为当日成功。

## 调整时间、路径和重新安装

修改本机每日执行时间，例如改为凌晨 01:00：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-backup-sync.ps1 -ServerHost '<服务器地址>' -KnownHostsFile '<已核验的known_hosts路径>' -DailyAt '01:00' -RunNow
```

指定其他备份目录：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/install-backup-sync.ps1 -ServerHost '<服务器地址>' -KnownHostsFile '<已核验的known_hosts路径>' -DailyAt '00:00' -Destination 'D:\Application\WhereToGo\backups'
```

时间格式是 `00:00` 到 `23:59`。Windows 当前时区为中国标准时间（UTC+8），与香港一致。时间修改是更新当前用户的任务；任务脚本从安装目录运行，项目目录移动不会影响已安装任务。

服务器生成时间独立配置在 `/etc/systemd/system/wheretogo-backup.timer.d/download-schedule.conf`。当前 CentOS 7 的旧版 systemd 不支持 `OnCalendar` 的时区后缀，文件中的时间按服务器 UTC 解释。若要调整为新的拉取时间之前十分钟，请先换算 UTC，再修改该文件并执行：

```bash
systemctl daemon-reload
systemctl restart wheretogo-backup.timer
systemctl list-timers wheretogo-backup.timer
```

停用本机拉取：

```powershell
Disable-ScheduledTask -TaskName WhereToGo-EncryptedDatabaseBackup
```

停用任务不会删除已有备份，也不会停止服务器生成备份。

## 加密归档可读性校验

已安装官方 age 1.3.2 到 `D:\Application\Age`。校验最新本机归档：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts/verify-local-backup.ps1
```

脚本从 DPAPI 解开恢复密钥，仅通过内存流交给 age，完整验证加密认证标签，并检查归档中的 SQL 含三个数据库。不会将明文 SQL、私钥或凭据写入临时文件。已对实际下载文件执行成功。

此校验不等于已把 SQL 恢复进一个全新的 PostgreSQL 实例。本次没有执行完整恢复或灾难恢复用时演练。

## 恢复与保管

至少另行保管一份 age 恢复私钥，以及独立介质上的加密归档。DPAPI 与当前 Windows 用户配置有关，重装系统或丢失该用户配置可能无法解开本机的密钥文件，不能只依赖这台电脑。

真正恢复前，使用**隔离的 PostgreSQL 16 + PostGIS 环境**，不要指向当前服务器或本机业务实例。age 解密后检查 `database.sql` 与私有配置，先恢复数据库角色及三个数据库，再以原加密密钥和身份 issuer 配置启动应用，验证旅游、账本及凭据解密。确认恢复结果后再考虑切换正式入口。

## 在新机器重新建立下载

1. 安装 Python 及 paramiko，安装路径放在 D 盘应用目录。
2. 运行 `scripts/install-backup-sync.ps1`，生成该 Windows 用户自己的 DPAPI 下载私钥和只读公钥。
3. 将 `download-key.pub` 及 `deploy/vps/backup-export.py`、`configure-backup-download.sh` 传到服务器，通过管理员 SSH 执行配置脚本。
4. 新机器首次连接需要另外核对服务器主机指纹；不要关闭主机指纹验证。
5. 手动运行下载、检查任务后台结果，再核对归档解密校验。下载私钥与 age 恢复私钥是两份不同用途的密钥。

部署脚本不会把电脑的下载私钥上传到服务器。`configure-backup-download.sh` 中的专用公钥授权会替换该账号当前授权，如需多台电脑同时下载，应明确添加各自的只读公钥，而不是共享私钥。
