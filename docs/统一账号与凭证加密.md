# 统一账号与凭证加密

更新：2026-10-25。业务后端继续使用 Java 8。身份服务独立使用 Keycloak 26.8.1 和 Java 21，不修改系统默认 Java。

## 1. 本机使用

地址：

| 页面 | 地址 |
| --- | --- |
| 门户 | http://localhost:5173/ |
| 账号与安全 | http://localhost:5173/account/ |
| 旅游 | http://localhost:5173/travel/ |
| 记账 | http://localhost:5174/ |
| 本人资料、密码、验证器及会话 | http://localhost:8091/realms/local/account/ |
| 门户账号管理 | http://localhost:8091/admin/local/console/ |
| 身份服务恢复管理 | http://localhost:8091/admin/ |

首次安装及启动，在仓库根目录执行：

```powershell
./scripts/install-identity.ps1
./scripts/start-local.ps1
./scripts/show-initial-account.ps1
```

门户初始用户名为 `admin`，随机初始密码通过最后一条命令在你本机显示，首次登录必须修改。修改后该命令仍只显示原初始值，请使用修改后的密码。不要将输出粘贴到代码、工单或公开聊天中。

门户管理员可用同一个 `admin` 账号在“账号与安全 → 管理门户账号”创建、停用用户及分配角色。角色 `portal-admin` 控制管理入口显示；身份服务的 `realm-management/realm-admin` 决定真正的管理权限，隐藏入口不替代服务端权限检查。普通用户只有本人账号中心。

`show-initial-account.ps1 -Administrator` 显示独立的身份服务恢复管理员 `identity-admin`。它是 Keycloak 的临时 bootstrap 管理员，仅用于初始化和恢复；正式部署应先创建持久管理员、启用 MFA，再删除临时管理员。门户日常管理使用 `admin`，不需要恢复管理员。

新用户有独立的数据空间，不会继承原本地超管数据。要访问原数据，使用保留 subject=`local-demo-user` 的初始门户账号。不要随意更改 realm、issuer 或这个 subject。

## 2. 安装与数据位置

| 内容 | 本机位置 |
| --- | --- |
| Keycloak | `D:\Application\Keycloak\keycloak-26.8.1` |
| 身份服务独立 Java | `D:\Application\Jdk-21\runtime` |
| 原 Java 8 业务运行时 | `D:\Application\Jdk-1.8\jdk-1.8` |
| 身份库 | PostgreSQL 的 `portal_identity`，独立 `portal_identity` 数据库角色 |
| 加密凭证 | SmartLedger 库的 `ledger_provider_credentials` |
| 本机 AES 密钥 | `D:\Application\WhereToGo\secrets\credential-keyring.json` |
| 初始化凭据 | 同目录 `identity-bootstrap.clixml`，Windows DPAPI 加密 |
| 服务日志 | `D:\Application\WhereToGo\logs` |

密钥目录只给当前 Windows 用户与 SYSTEM 访问权限。AES 密钥文件自身是服务可读取的密钥，不声称其被 DPAPI 加密；DPAPI 用于 bootstrap 密码。运行身份服务的账号密码、签名键和登录密码哈希由 Keycloak 数据库保存。Keycloak 的账号密码采用哈希验证，业务应用不保存登录密码，也无法查询其原值。

身份服务绑定 `127.0.0.1:8091`。本机使用 HTTP 和 `start-dev`，不能直接开放公网。生产部署参见第 6 节。

## 3. 登录与退出

门户首页免登录浏览，右上角提供登录和注册。进入旅游、记账、账号中心或 API 管理时要求登录，返回门户仍可浏览首页。两个公共 SPA 客户端是 `wheretogo-web` 与 `smartledger-web`，共用同一 realm，使用 Authorization Code + PKCE S256，无 SPA client secret。已启用自助注册，新用户不获得管理员权限。两个 SPA 的密码直接授权与 implicit flow 保持关闭；邮件重置仍需配置 SMTP。

注册使用 OIDC `prompt=create`，不自行拼接无 state 的注册跳转。登录/注册成功返回最初请求的应用；从门户进入记账时先完成门户登录，再通过身份服务已有 SSO 会话打开记账，不在应用间传递访问令牌。两个客户端必须保留 `basic` 默认 client scope，以提供 API 必需的 `sub` 标识。

登录页主题位于 `identity/themes/personal`，继承 Keycloak 自带表单、校验、密码显示按钮及 MFA 页面。桌面采用品牌说明加表单卡片的两列布局，窄屏收为居中单列；明暗颜色跟随系统。登录、注册页均有“返回门户首页”。启动脚本同步主题，生产 Compose 以只读方式挂载主题，并设置 `PORTAL_ORIGIN`。

一个账号在身份服务中登录后，切换记账时通过顶层 OIDC 跳转复用已有 SSO 会话。门户/旅行共用一个客户端，记账仍领取自己的 audience 令牌，不在地址栏、跨域消息或 localStorage 中传递访问令牌。

每个前端使用以下固定端点：

- `/auth/callback`：带 state、PKCE 校验的登录回调，返回地址限制为本应用。
- `/auth/silent`：静默续期和会话检查回调。
- `/auth/signed-out`：退出回调。
- `/auth/frontchannel`：校验 issuer 和 sid 后广播本 origin 退出事件。

“退出所有应用”调用身份服务的 RP-Initiated Logout；应用移除当前令牌，以 front-channel、同 origin storage 事件、OIDC 会话监测及恢复焦点检查同步其他标签页。账户被冻结、其他设备结束会话时，前端检测到后停止使用该登录状态。不会删除账号名下的 IndexedDB 账本。

Access token 有效期默认 5 分钟。业务 API 离线验签，已复制出去的令牌可能继续有效至过期；本轮没有实现逐 token 即时撤销。浏览器禁止第三方 Cookie、标签页休眠或网络中断也可能延迟会话检测。生产建议门户、记账、身份服务使用同一父域的 HTTPS 子域；不能承诺任意跨站部署都支持隐藏 iframe SSO。

浏览器内的 OIDC 令牌与 PKCE 状态仍在 sessionStorage 中，同源脚本可访问。它们不是登录密码；本轮没有实现 HttpOnly Cookie BFF 架构。

## 4. 坚果云凭证

### 加密结构

用户名和第三方应用密码作为一个 JSON 负载用 **AES-256-GCM** 加密。每次保存生成新的 12 字节随机 nonce，认证标签 128 位，关联数据包含版本、用途、issuer、subject。用户之间替换密文无法通过校验。

数据库只保存 `user_id`、`key_id`、nonce、密文及更新时间，不保存明文用户名或应用密码。密钥来自环境变量或外部文件，不写入数据库、仓库、前端构建或账本快照。

接口：

| 接口 | 行为 |
| --- | --- |
| `GET /api/v1/sync/nutstore/credentials` | 仅返回可用性、已配置状态、脱敏邮箱、更新时间；密码不返回 |
| `PUT /api/v1/sync/nutstore/credentials` | 保存当前登录用户的邮箱和应用密码，服务端加密 |
| `DELETE /api/v1/sync/nutstore/credentials` | 删除当前登录用户的凭证 |
| `POST .../test` | 从凭证库加载，测试连接，不接收密码 |
| `POST .../upload` | 请求只包含 snapshot，后端加载凭证 |
| `POST .../download` | 后端加载凭证并恢复快照 |

页面保存成功后清空输入框，只显示脱敏邮箱和配置状态。更换配置需重新填写完整邮箱和应用密码。旧 localStorage/sessionStorage 凭证在所属账号成功迁入服务器后删除；其他未打开过的账号或其他浏览器无法由本机页面远程清除。迁移失败会保留旧配置以便重试，不会宣称已经清理成功。

配置缺少密钥时，凭证接口不会退回明文存储。已有密文无法解密时，状态会要求重新配置或恢复原密钥；删除配置仍可使用。

后端同步时需要解密应用密码并使用 Basic 认证连接固定的 HTTPS WebDAV 地址。服务器进程能接触明文，不是对服务器保密的端到端加密。生产前端到 API 必须 HTTPS；本机回环 HTTP 不提供 TLS。

### 配置与轮换

选择一种服务端配置：

```text
SMARTLEDGER_CREDENTIAL_KEY_FILE=/run/secrets/credential-keyring.json
```

或通过平台 Secret 注入 `SMARTLEDGER_CREDENTIAL_KEYRING`。格式：

```json
{"activeKeyId":"v2","keys":{"v1":"<旧的32字节随机密钥的Base64>","v2":"<新的32字节随机密钥的Base64>"}}
```

不能把示例占位符直接作为密钥。可用操作系统 CSPRNG 或 `openssl rand -base64 32` 生成。切换 activeKeyId 后，新保存使用新密钥，旧数据继续使用记录中的 key_id 解密。逐账号重新保存凭证后，确认数据库中没有旧 key_id 才能移除旧密钥。当前没有全库自动轮换任务。

数据库与密钥必须分开备份，密钥备份本身也应受保护。本机启动脚本检测到密钥标记存在而密钥文件丢失时会停止，不能用新随机密钥恢复旧密文。DPAPI bootstrap 文件只能由原 Windows 用户解密，不是跨机器恢复方案；身份数据库备份与独立恢复账号同样需要保管。

### 数据加密边界

这次加密的是坚果云邮箱和第三方应用密码。IndexedDB 账本、API 云快照、坚果云 JSON 备份和导出文件没有新增内容加密。不要把“凭证已加密”理解成整个账本的端到端加密。

## 5. 账号准入

后端生产默认保留 `API_ALLOWED_SUBJECTS` 白名单。创建新账号后，需把实际 sub 加入两个服务的白名单；也可以明确设置 `API_ALLOW_ANY_AUTHENTICATED_USER=true` 并清空白名单，使这个私有 realm 中的有效账号可使用两个业务服务。业务数据始终按 issuer/subject 分隔。

身份库负责账号、密码、MFA、SSO 会话和角色。旅行与记账仍是独立数据库，不能直接修改它们的 user_id 来模拟账号合并。

## 6. 生产部署

1. 用自己的 HTTPS 域名和数据库，保持两个前端配置的 `VITE_OIDC_AUTHORITY` 完全一致，例如 `https://identity.example.com/realms/personal`。两个 API 的 issuer 也必须完全一致。
2. 生成不含用户或密码的生产 realm：

   ```powershell
   $env:PORTAL_ORIGIN='https://portal.example.com'
   $env:LEDGER_ORIGIN='https://ledger.example.com'
   $env:IDENTITY_REALM='personal'
   node ./scripts/generate-identity-config.mjs
   ```

3. 使用 `identity/docker-compose.yml` 与 `identity/.env.example` 配置独立身份库。将生成目录作为只读 import 挂载，配置强数据库密码、bootstrap 管理员密码、真实 HTTPS hostname、实际反向代理 CIDR。HTTPS 终止代理必须覆盖客户端转发头；应用端口仅绑定回环。
4. 生产启动使用 `start`，禁止 `start-dev`。导入只在 realm 不存在时进行，之后通过管理员界面/API 修改，不覆盖正在使用的 realm。不要将 `realm-local.json` 直接用于公网：它含 HTTP 本地地址和本地初始化用户。
5. 管理员创建正式账号，必要时赋予 `portal-admin` 及 `realm-management/realm-admin`；普通用户不授予这两个管理权限。创建持久恢复管理员后移除临时 bootstrap 管理员。
6. 启用 MFA，按实际邮箱服务配置 SMTP、邮箱验证及邮件重置。默认没有 SMTP，所以不显示已经可用的邮件找回能力。
7. 通过平台 Secret 注入凭证密钥；更新运行账号的 `ledger_provider_credentials` 表权限；运行 Flyway V2 后启动记账 API。
8. 两个前端都设置 `VITE_LOCAL_MOCK_AUTH=false`，构建产生静态安全头与回退规则。frontchannel 回调需要允许身份服务框架嵌入；其余路由仍使用 SAMEORIGIN。

Keycloak 自托管需要持续运行的计算资源与独立身份数据库。仓库提供部署配置，不代表某个免费平台会免费长期运行该进程；也可以使用兼容 OIDC、会话检测、退出端点的托管身份服务，但账号管理链接和角色映射需按该服务适配。
