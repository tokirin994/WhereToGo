# 旅游应用升级：独立旅行空间

> 2026-10-25 后续已接入默认 Photon 搜索、Open-Meteo 天气、OSRM 道路路线及酒店跳转，并增加多协议 AI 和专项测试。下文是上一阶段的架构记录，其中“未接入”“默认关闭”等服务状态以 [最新服务接入与分期验收](./旅游服务接入与分期验收.md) 为准。

## 参考与设计

本轮参考 [The Travel Atlas](https://travelatlas.co/) 的公开页面及公开前端所展示的旅行创建、偏好设置、每日行程、地点地图和旅行管理流程，结合本项目的统一门户与 SmartLedger 实现自己的界面和数据模型。未复制对方源码、游记、图片或酒店数据。

入口为 `/travel/`，门户仍在 `/`；进入旅行空间使用现有统一账号。桌面使用侧栏、卡片列表和行程／地图双栏，手机使用底部导航和单栏内容。浅色、夜间、跟随系统共用语义颜色；所有新增交互使用实际图标与中文标签。

## 已实现的业务

| 模块 | 本次能力 | 数据与约束 |
| --- | --- | --- |
| 我的旅行 | 状态筛选、名称／目的地搜索、创建、编辑、复制、删除 | 后端按当前账号隔离；最多返回 500 趟；单趟新建／编辑最多 60 天 |
| 创建向导 | 目的地与日期、人数、节奏、兴趣、交通、预算、必做与避开内容 | 偏好随旅行存入 PostgreSQL；预算与计划费用均为人民币 |
| 每日计划 | 自填活动／交通、收藏地点、时间、停留、备注、计划费用、完成标记 | 最多 300 项；日期必须在旅行范围内；日程 ID 在编辑时保留 |
| 排序与改期 | 拖动、菜单前后移动、从 09:00 顺排、时间冲突提示、改期同步平移 | 顺排固定留出 30 分钟，不声称为实际交通时间；缩短日期前需要移出超范围安排 |
| 真实地图 | WGS84 点位、每日编号、直线连接、手动选点、当前定位、全屏 | 无坐标不绘制虚假位置；直线不作为导航；底图依赖网络 |
| 收藏库 | 分类／城市／名称／标签搜索、收藏、去过、备注、来源链接、地点编辑删除 | 单账号最多 500 个地点；删除地点后保留已有行程的文字快照并解除引用 |
| 地点合集 | 创建、编辑、删除、多选成员、在地点详情中加入合集 | 单账号最多 500 个合集；只能包含当前账号的已保存地点 |
| 出行辅助 | 清单、旅行备忘、完成统计、预算超额提示 | 全部保存到旅行数据；不替代 SmartLedger 实际账务 |
| 独立旅行账本 | 在所选旅行打开 SmartLedger 对应旅行账本 | 继续使用既有认证和账本接口；不在 URL 放访问令牌 |
| 导入导出 | 可打印 HTML、JSON 备份与新建导入、ICS、本地复制行程文字 | JSON 不含账号令牌；最多 2MB；300 个日程；日历是浮动本地时间，请自行核对目的地时区 |
| 地点清单导入 | 名称、城市、分类、地址的多行清单；公开地图链接文本解析 | 每批 1–100 个，预览可改后再提交；不抓取任意 URL；不自动解析短链接跳转 |
| 灵感模板 | 城市、山野、美食、亲子四种可编辑结构和清单 | 自有结构模板，不是社区游记或真实景点推荐 |

## 编排能力及边界

### 收藏智能编排：可直接使用

在旅行里选择“智能编排 → 从收藏生成草稿”。只使用当前账号已经收藏、城市与目的地匹配的地点。多个目的地可用顿号或逗号分隔。

算法优先考虑必做关键词、兴趣及特别想去标记，排除避开关键词；慢／适中／充实节奏分别按每天约 3／4／6 个点分配，相同优先级下尽量靠近已有坐标的邻近点。多城市按文字匹配筛选，未提供跨城交通路线优化。关键词按名称、分类、标签匹配，不是语义搜索。

生成结果先进入预览，点击“应用”才替换原行程。没有收藏时提示先添加地点，不会编造景点、票价或营业时间。生成的时间、停留和间隔需要用户核对，未知费用保持 0（待填写）。

### 外部 AI：可选，默认关闭

只在后端配置兼容 `/chat/completions` 的 HTTPS 服务：

```dotenv
TRAVEL_AI_BASE_URL=https://your-provider.example/v1
TRAVEL_AI_API_KEY=replace-with-server-secret
TRAVEL_AI_MODEL=your-provider-model-id
```

以上均为格式示例，未选择或验证任何供应商。密钥只能放平台服务端环境变量／受保护文件，不能使用 `VITE_` 前缀。Windows 本机可在启动 PowerShell 中设置环境变量后运行 `scripts/start-local.ps1`；若旅游 API 已运行，需要重启该 API 后生效。根目录 `.env` 供 Docker Compose 读取，本机脚本不会自动导入它。

用户主动选择 AI 编排时，将本次旅行（包括备注、偏好、清单及已有安排）与最多 150 个相关收藏的名称、分类、标签、坐标发送给该服务。不会发送坚果云凭证、门户令牌或其他账号数据。请求前界面有说明。返回结果只接受候选地点 ID，检查所有权、日期、时间、时长、数量及重复项，先展示草稿；校验不能保证内容事实正确。

调用限额为单账号每分钟 2 次、UTC 每天 20 次、单实例同时 2 次；失败调用也消耗额度。计数存在实例内存，重启清空，多实例需在网关／共享存储统一计数。最多接收 512KiB 响应；连接超时 5 秒、读取超时 45 秒；不跟随跳转。

## 地图与名称查询配置

前端默认底图为 OpenStreetMap 标准瓦片，使用 Leaflet 1.9.4；保留可见署名、浏览器缓存与 Referer，不批量预取。遵守 [OSM 瓦片政策](https://operations.osmfoundation.org/policies/tiles/)。面向较大流量部署时应选择适当的商业／自托管瓦片服务，并按供应商要求调整署名。

```dotenv
# 前端公开配置：修改后重新构建
VITE_MAP_TILE_URL=https://tile.openstreetmap.org/{z}/{x}/{y}.png
# 后端：选择一个允许本应用调用的 Nominatim 兼容 search 端点
TRAVEL_GEOCODER_URL=https://your-geocoder.example/search
```

名称查询默认关闭，地图选点／手填坐标无需查询服务。必须由部署者选择并确认服务条款后再填写 `TRAVEL_GEOCODER_URL`；不默认调用公共 Nominatim。参见 [Nominatim 使用政策](https://operations.osmfoundation.org/policies/nominatim/)。只支持不含查询参数和内嵌凭证的 HTTPS 基础端点；当前适配器无供应商 API Key 参数，收费鉴权服务应通过自己维护的兼容代理接入。

名称查询仅点击按钮触发，无键入联想，单实例全局最短 1.1 秒间隔、缓存 15 分钟／最多 500 个查询，最多 5 个候选。查询文字会发送给配置服务，用户选中候选后仍需保存。新增 `/system/` 服务状态只表示是否填写配置，不表示供应商健康检查通过。

应用只接受 WGS84。高德 GCJ-02／百度 BD-09 不能直接当作 WGS84；地图链接文本只有 OpenStreetMap／Google 类域名会提取坐标，导入后仍需核对实际点位。

## 数据模型与迁移

Flyway `V6__travel_workspace.sql` 在已有 V5 数据上增量迁移，不清空表：

- `places` 增加 `favorite`、`visited`、`notes`、`source_url`。
- `trips` 增加 JSONB `preferences`：节奏、预算、人数、交通、出发地、兴趣、必做／避开、准备清单。
- `trip_stops` 增加 `estimated_cost NUMERIC(12,2)` 和 `completed`。
- 新表 `travel_collections` 与 `travel_collection_places` 保存当前用户的合集及成员关系。

正式部署前由迁移账号执行迁移，并参考 `deploy/database-runtime-grants.sql` 给业务账号授予两张新表所需权限。现有旧旅行偏好 `{}` 会读为默认值，旧地点默认未收藏／未去过，旧日程费用 0、未完成。复制旅行重置完成和清单勾选，保留原旅行；删除旅行不删除 SmartLedger 账本。

浏览器缓存继续按账号隔离。新账号不自动填演示数据；旧账号已有浏览器记录不强制删除。本机离线新建记录在恢复网络后编辑可提升为云端记录；云端已有记录写入失败会报错，不伪装成同步成功。合集仅支持后端保存，缓存可用于查看，不提供自动合并冲突解决或多人实时协作。

## API 扩展

所有接口继续经过统一 JWT、账号授权、请求大小和速率限制；本轮未新增匿名业务接口。

| 接口 | 用途 |
| --- | --- |
| `POST /api/v1/trips/{id}/duplicate` | 当前账号旅行副本 |
| `POST /api/v1/trips/import` | 事务内新建旅行和日程，失败整体回滚 |
| `PUT /api/v1/trips/{id}` | 偏好／状态；`shiftStops=true` 时平移原安排 |
| `PUT /api/v1/trips/{id}/stops` | 保存费用／完成状态，保留属于该旅行的日程 ID |
| `POST /api/v1/places/batch` | 事务批量保存地点 |
| `GET/POST /api/v1/collections` | 列表／创建合集 |
| `PUT/DELETE /api/v1/collections/{id}` | 编辑／删除合集 |
| `GET /api/v1/planner/status` | 配置标志和 AI 日限额 |
| `POST /api/v1/planner/trips/{id}/draft` | `{strategy:"local"}` 或 `{strategy:"ai"}` |
| `GET /api/v1/maps/status` | 是否配置名称查询 |
| `GET /api/v1/maps/search?query=…` | 用户主动查询地点候选 |

## 未接入的能力

尚未接入公开社区／多人共享链接、游记抓取、真实酒店报价与预订、天气、实时公交／驾车导航。复制分享是行程文字或文件，不是匿名访问的云端公开旅行页。AI 与名称查询的供应商调用尚未做真实凭证联调，浏览器当前也未完成逐项交互验证。

本轮只进行前端 TypeScript／生产构建、Java 8 编译打包及本机服务启动日志检查，没有新增或运行功能测试。后续如需验收，可使用现有账号按创建 → 收藏 → 编排预览 → 编辑排序 → 改期 → 导出导入 → 旅行账本逐项确认。
