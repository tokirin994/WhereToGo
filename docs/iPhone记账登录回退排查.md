# iPhone 记账登录后返回登录页

## 后续截图确认的根因：同步写入认证头重复

后续诊断截图明确显示 `PUT /api/v1/sync/snapshot` 返回 401。服务器中该请求编号对应认证阶段拒绝，未进入业务控制器。

请求封装原来使用：

```typescript
{...Object.fromEntries(new Headers(options.headers)), Authorization: currentBearer}
```

`Headers` 将调用方字段规范成小写 `authorization`，后面又出现大写 `Authorization`。浏览器最终按大小写不敏感的规则合并两者，发出两个逗号连接的 Bearer 值。云同步 PUT 原来会显式传入认证头，因此稳定触发；同样存在重复 `Content-Type` 的风险。

使用专用测试账号、同一有效令牌及不会覆盖快照的过期版本条件对照验证：

| 请求 | 服务器结果 |
| --- | --- |
| GET，单个认证头 | 200 |
| PUT，单个认证头，故意使用不匹配的版本 | 409，正常进入同步版本检查 |
| PUT，重复认证头，其余内容相同 | 401 `invalid_token` |
| PUT，单个认证头，非法快照结构 | 400，正常进行数据校验 |

因此这里不能再只归因于设备或 Cookie。开启自动云同步且需要上传的设备，打开页面时会走到出错的写入路径。其他设备是否开启同步、是否已经有云端快照会改变触发条件；未逐台检查设备设置，不能断言某台设备的具体配置。

修复统一使用 `Headers.set()` 覆盖认证及 JSON 类型字段，并移除同步层重复传入的凭证。门户、旅行的同类请求头合并代码一起修正。后台认证规则未放宽，写操作不会因 401 被自动重复提交。

新增自动测试先在旧代码下失败：三种认证字段大小写均产生双 Bearer，首次自动同步上传返回 401；修复后必须同时通过。

移动模式 WebKit 另加实际上传回归 `--cloud-sync-write`：只接受显式 `WTG_ALLOW_SYNC_WRITE=true` 和匹配的 `WTG_SYNC_TEST_SUBJECT`，同时确认专用账号没有云端快照和已有账本，再创建带唯一测试账本 ID 的空快照。浏览器开启“打开应用时同步”，由真实记账工作区上传，随后读回并核对 revision=1、账本标记和零流水。报告只能保存到本机忽略目录。测试后按测试主体、版本号、内容哈希和测试账本 ID 精确清理测试快照；不得清理或覆盖其他用户数据。

这项回归验证真实 PUT 成功，补充了之前只有读取和故障注入的覆盖空缺。

## 已确认的代码路径

用户报告 iPhone Safari 登录记账后几秒出现“登录已过期，请重新登录”；iPad 和 iPhone 上的旅行应用没有同样现象。

这个提示来自记账前端。原来 `authorizedRequest()` 对 GET 的 401 做一次刷新重试后，仍失败就发送 `smartledger-session-expired`；写操作收到一次 401 也发送此事件。根组件收到事件后直接把界面用户设为 `null`。这使记账接口的拒绝直接变成整页登录回退，不能区分当前令牌、旧请求、接口策略和统一会话真正失效。

另有两处会放大问题：

- 打开旅行账本失败时，通用 `error` 会使根组件显示登录页，即使已有用户仍然有效。
- 登录回调收到用户信息后，原来能够在回调文档里挂载记账工作区，提前启动账本请求。现在回调只完成身份处理与跳转，正式入口才挂载工作区。

这些是可导致同类现象的实现缺陷。截图没有包含网络状态或请求编号，因此尚不能断言这台 iPhone 上首次拒绝的具体原因，也不能仅凭设备差异归因于 Safari Cookie 策略。设备上的历史会话、本地数据和请求顺序可能不同，需按实际反馈确认。

## 修正行为

| 情况 | 当前处理 |
| --- | --- |
| GET 返回 401，刷新后成功 | 返回成功结果，继续使用记账 |
| GET 刷新后仍是 401 | 保留工作区，显示连接提示和可展开的请求诊断 |
| 写操作返回 401 | 不自动重发，不伪装保存成功；保留工作区并提示重新连接 |
| 切换账号后，旧请求才返回 401 | 不重试旧会话，不影响新的登录状态 |
| 403、429、服务器或网络错误 | 按请求错误处理，不宣告统一账号退出 |
| 旅行账本入口失败 | 保留日常记账界面，并显示本次操作的错误 |
| 用户点击“重新连接” | 使用该记账客户端发起一次顶层 `prompt=none` 授权，取得新授权；不依赖 iframe Cookie，不自动循环跳转 |
| 统一账号确认续期失效、其他页面退出或切换账号 | 仍结束相应会话；显示对应原因 |

诊断只展示 HTTP 状态、请求方法、去掉查询参数并隐去 UUID 的接口路径、服务器请求编号。不会展示密码、JWT、Cookie、账目内容或服务 Key。后端 JWT、issuer、audience 和按用户隔离的权限检查保持有效。

## 验证

```powershell
npm test
npm run check:boundaries

# 环境变量和工具安装方法见《Safari兼容与统一登录回归.md》。
node scripts/test-webkit-sso.mjs --bundle-dir .local/safari-release/dist --mobile --rejected-api
node scripts/test-webkit-sso.mjs --mobile --rejected-api
```

故障注入会主动使账本 GET 连续返回 401，检查刷新重试、等待 10 秒后工作区仍保留，再通过“重新连接”取得新的静默授权并恢复真实 API。整个阶段禁止 iframe 导航，验证免再次输入密码的第一方授权路径。不会创建业务流水或修改服务 Key。

另有组件测试覆盖：登录回调不挂载工作区、旅行账本 503 不显示登录页、API 401 不清空界面用户、统一会话确实失效时正常结束会话；共享身份测试覆盖诊断原因不包含令牌。

WebKit 自动化不等同于 iPhone 真机复现。此次修复后仍需用户在出现问题的手机确认。

## 手机端复查

重新打开部署后的记账入口，使用带版本查询参数的新链接可以避开旧标签页的返回缓存，同时保留原有 IndexedDB 账本。不要清除 Safari 网站数据：本地未同步账目可能因此丢失。

如果仍出现问题，记录页面提示；若显示连接提示，展开“查看连接诊断”，提供状态及请求编号。若显示统一账号续期拒绝或其他页面退出，将沿相应会话路径继续排查。
