# 量芯云完整服务部署与运维

部署日期：2026-10-28（香港时间）。本文地址、服务器地址及账号名使用占位信息；实际参数在本机受保护的部署配置中保存。最新结构图见 [系统结构与部署实例](系统结构与部署实例.md)。

## 访问入口

| 应用 | 地址 |
| --- | --- |
| 个人门户 | https://personal.example.com/ |
| WhereToGo 旅游 | https://personal.example.com/travel/ |
| SmartLedger 记账 | https://personal.example.com/ledger/ |

三个入口在同一 HTTPS 域名下，旅游与记账使用同一套账号登录，分别持有自己的 API 令牌。门户公开浏览，业务数据需要登录。

地址通过 sslip.io 根据服务器公网 IP 解析，不需要购买域名、注册 Cloudflare 或运行本机隧道。服务器 IP 不变时地址保持不变；它依赖第三方免费 DNS 服务，不代表永久域名所有权或服务可用性承诺。

HTTPS 使用已签发的 Let's Encrypt 证书，由 Caddy 自动续期。云端不设置八小时体验到期时间，家中电脑关机不会关闭服务器服务。仍需保持云服务器及其公网 IP 有效，并按量芯云账单续费。

旧的本机 Quick Tunnel 分享环境已停止，其独立数据库和会话文件保留。原本地旅行和记账数据没有自动上传到服务器；云端是新数据空间，可通过应用中的导入或同步功能迁移自己的记录。

## 账号

初始账号及供朋友使用的独立账号在本机受保护的凭据文件中查看，每个账号的数据独立。现已开放自助注册：门户右上角及统一登录页都有“创建账号”入口。注册成功即登录，可使用两个应用；新用户不会获得管理员角色。

在本机项目根目录查看初始密码：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\scripts\show-vps-accounts.ps1 -Username '<用户名>'
```

填写实际用户名可查看该账号的初始密码。修改应用密码后，该文件不会自动更新，保存的是部署时的初始密码。

账号密码文件位于 `D:\Application\WhereToGo\remote-deploy\22576\accounts.clixml`，通过当前 Windows 用户的 DPAPI 加密。不要把该文件提交到仓库。服务器上的一次性明文账号文件和 realm 导入文件已在完成登录验证后删除。

正常用户可从门户“账号与安全”管理自己的资料、密码和会话。Keycloak 管理控制台不对公网开放，生产门户隐藏管理控制台快捷链接。业务 API 接受本系统签发、受众匹配且有效的账号令牌；按 issuer + subject 隔离每个人的数据。无需手动把新注册账号加进白名单。请勿重新启用开发模拟登录。

## 实际部署结构

- 服务器：`<SERVER_HOST>`，SSH 端口 22，当前系统 CentOS 7，2 核、4GB 内存。
- Docker 28.5.2 静态兼容安装，Compose v2.40.3。
- Java 8：两个业务后端；Java 21：独立的 Keycloak 26.8.1 容器。
- PostgreSQL 16.15 + PostGIS，分别建立旅游、记账、身份数据库。
- Caddy 2.11.7：HTTPS、前端静态文件、路径反向代理。
- 账号、数据库、密钥均为本次云端部署新建，没有复制本地的坚果云账号密码。

业务 API 以非 root 用户运行，根文件系统只读，移除 Linux capabilities，并限制内存、线程、数据库连接与日志。数据库未映射宿主机端口，Keycloak master realm 和管理路径不经公网网关转发。

内存上限：数据库 768MB、Keycloak 768MB、每个业务 API 512MB、网关 128MB。完成登录检查后的容器实际总占用约 1GB；该数值不是负载测试结论。

主机输入防火墙允许 TCP 22/80/443、回环、已建立连接及 ICMP。Docker 发布端口走转发链，本套服务只发布网关 80/443。服务端未开放 Docker TCP 管理接口。

## 日常管理

SSH 登录服务器后：

```bash
cd /opt/wheretogo/current
docker compose ps
docker compose logs --tail=100 travel-api ledger-api identity gateway
```

启动、停止或重启整个应用栈：

```bash
systemctl start wheretogo-stack
systemctl stop wheretogo-stack
systemctl restart wheretogo-stack
```

仅重启一个应用：

```bash
cd /opt/wheretogo/current
docker compose restart travel-api
```

`docker.service`、`wheretogo-stack.service`、`wheretogo-firewall.service` 和 `wheretogo-backup.timer` 已启用。已确认它们当前处于运行状态，未为验证配置而重启操作系统。

服务器 DNS 已改为 1.1.1.1 与 1.0.0.1，并写入 eth0 的静态 DNS 配置。原设置备份在 `/opt/wheretogo/incoming/resolv.conf.before-deploy` 和 `ifcfg-eth0.before-dns`；IP、网关和网卡地址未改动。

## 加密与备份

- 登录密码由 Keycloak 进行口令哈希后存储。
- 坚果云账号与应用密码由后端 AES-256-GCM 加密，密钥文件独立于数据库，使用 issuer 与 subject 绑定身份。网页不回显应用密码。
- PostgreSQL 内的普通账目未做逐字段或整库加密。内部网络隔离、访问授权和备份加密不等于整库加密。
- 应用上传到坚果云的账本 JSON 仍没有端到端内容加密；这与同步凭据加密是两项不同能力。

每日自动备份在服务器 UTC 15:50（香港时间 23:50）触发，备份 PostgreSQL 全量数据和恢复所需的私有配置，使用 age 公钥加密。解密私钥已移出服务器；服务器仅保留加密公钥。临时明文数据库导出在加密完成后删除。

立即执行备份：

```bash
systemctl start wheretogo-backup.service
systemctl list-timers wheretogo-backup.timer
ls -lh /opt/wheretogo/backups
```

首份备份及恢复密钥已复制到本机：

- 加密备份：`D:\Application\WhereToGo\remote-deploy\22576\20261027T162113Z.tar.age`
- 恢复密钥：同目录 `backup-recovery-key.clixml`，由当前 Windows 用户的 DPAPI 加密。

本机现已配置午夜 00:00 的计划任务，将服务器加密归档拉取至 `D:\Application\WhereToGo\backups`。支持登录后补执行，任务最近实际执行结果为成功。当前没有自动删除策略，需监控磁盘占用；仍建议另外保管独立介质副本。

DPAPI 与当前 Windows 用户有关，重装 Windows 或丢失用户配置可能影响解密。恢复私钥应另外保管到自己控制的安全位置，不能只依赖这台电脑。

恢复时先在隔离的新数据库环境演练：用 `age -d -i <恢复私钥文件> <备份.tar.age>` 解密，解包得到 `database.sql`、私有配置与原公开地址；然后使用管理员身份恢复 PostgreSQL。不要直接覆盖正在使用的数据。更换公开域名时需迁移两个业务数据库的 issuer 绑定，并处理坚果云凭据的身份绑定加密。

## 更新代码

生产部署相关文件在项目 `deploy/vps/` 下。它们包含安装、构建打包、初始化、Compose、网关、防火墙和备份脚本，不含服务密码。

本机生成新的生产包：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\deploy\vps\build-package.ps1 -PublicOrigin 'https://personal.example.com'
```

将输出目录上传到服务器新的 release 目录，保留现有 `/opt/wheretogo/secrets` 和数据库目录，进入新目录执行 `bash activate.sh`。首次部署额外需要 `install-runtime-centos7.sh`、`install-backup-tool.sh` 及 `configure-operations.sh`。

上线前先备份，再验证新 release。前端构建固定公开地址，改 `.env` 不会改变已编译的前端；域名变更需要重新构建两套前端并更新 Keycloak 回调和后端 issuer。

`VITE_ADMIN_CONSOLE_ENABLED=false` 用于隐藏公网不可用的管理控制台链接，`VITE_REGISTRATION_ENABLED=true` 显示注册入口；实际注册由 Keycloak 的 `registrationAllowed=true` 控制，两个 API 需同时设置 `API_ALLOW_ANY_AUTHENTICATED_USER=true` 且清空 `API_ALLOWED_SUBJECTS`。业务后端仍保持 Java 8。AI 服务未配置付费服务密钥，使用外部 AI 前需要单独填写服务地址、模型与服务端密钥。
