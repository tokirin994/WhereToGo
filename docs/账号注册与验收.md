# 统一账号注册与验收

适用：个人门户、WhereToGo、SmartLedger。文中的 `https://personal.example.com` 是占位地址，运行时替换为实际部署域名。

## 使用入口与交互

- 门户右上角及统一登录页提供「创建账号」，门户不再展示额外的注册宣传卡。未登录也能浏览门户。
- 点击任一应用时进入统一登录页；登录按钮下方有独立的「创建账号」按钮。
- 注册页填写用户名、邮箱、密码及确认密码。姓名默认折叠为可选资料，可以之后在账号中心补充。
- 用户名 3–64 个字符；密码至少 12 位，包含大小写字母、数字及符号。邮箱、重名和密码错误在相应字段反馈，保留非密码输入。
- 登录页与注册页可互相切换，沿用原来的应用目标。注册后自动登录；从门户主动注册返回门户并显示欢迎提示；从应用登录页进入注册则继续原来的应用。
- 两个应用共享同一个账号与身份会话，各自持有受众不同的访问令牌。注册不会授予 `portal-admin`，也不会读取其他账号的数据。

账号密码交给 Keycloak 处理并以口令哈希存储，业务前端不另存一份密码。注册请求使用 HTTPS、授权码、PKCE 和 OIDC state。回跳限制在本应用允许的相对路径内。

## 邮箱与密码找回的当前限制

目前未配置 SMTP，因此没有邮件验证或邮件找回密码入口。注册可填写自己的常用邮箱，并可使用邮箱登录；邮箱此时**未经验证**，不能用作已验证身份或找回密码的凭据。不要填写他人的邮箱。忘记密码暂时需要管理员通过服务器上的身份管理服务处理。

要开放邮箱验证与自助找回密码，先配置可用的 SMTP 服务、发件人及其专用凭据，实际验证邮件收发成功后，再启用 realm 的 `verifyEmail` 与 `resetPasswordAllowed`。邮件凭据放服务器私有配置，不提交到仓库。

## 生产配置与升级

三个配置需要同时生效：

| 层 | 当前设置 |
| --- | --- |
| 两个前端 | `VITE_REGISTRATION_ENABLED=true`，生产构建时写入 |
| Keycloak personal realm | `registrationAllowed=true` |
| 两个业务 API | `API_ALLOW_ANY_AUTHENTICATED_USER=true`，`API_ALLOWED_SUBJECTS` 为空 |

“允许认证用户”仍校验发行者、受众、有效期和签名，不接受其他系统的令牌。API 按用户身份隔离数据并执行现有配额限制。不要启用本地模拟登录。

`deploy/vps/activate.sh` 调用 `configure-registration.sh`，通过容器内部管理接口调整已经存在的 realm。`configure-registration.py` 合并现有用户资料配置：姓名改为可选，添加字段提示；保留其他自定义属性和校验。升级不删除用户、不重设密码、不重新初始化数据库。

登录主题继承 `keycloak.v2`，定制 `login.ftl` / `register.ftl`，使用 Keycloak 原生字段、校验、密码显示切换与动态密码校验宏。模板基于 [Keycloak 26.8.1 登录主题](https://github.com/keycloak/keycloak/tree/26.8.1/themes/src/main/resources/theme/keycloak.v2/login)，升级身份服务版本时应一起复查模板兼容性。注册使用官方支持的 [`prompt=create`](https://www.keycloak.org/docs/26.1.5/server_admin/#_registration-requested-by-client)。

要重新关闭自助注册：在 realm 关闭 `registrationAllowed`，重建前端隐藏注册入口。仅关闭注册不影响已有用户；如需恢复邀请制，还要设置允许的用户 subject 白名单，并关闭两个 API 的公开认证用户准入。发布脚本默认开启注册，调整策略后应同步修改脚本，防止下次发布覆盖。

## 本地自动化检查

在项目根目录，Node/Maven/Java 需已在 PATH 中：

```powershell
npm --prefix frontend test
npm --prefix smartledger/frontend test
mvn -f backend/pom.xml test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File deploy/vps/build-package.ps1 -PublicOrigin 'https://personal.example.com'
```

前端注册回归覆盖入口、等待状态、应用目标、注册欢迎提示，以及两个客户端的安全回跳路径和 OIDC 参数。现有旅游、记账功能一起回归。生产构建会执行类型检查并打包 Java 8 后端及两个前端。

## 公网真实注册与 API 检查

下面的脚本会在自己的服务上创建独立测试账号，需要显式参数确认该行为：

```powershell
$env:WTG_PUBLIC_ORIGIN='https://personal.example.com'
node scripts/test-registration.mjs --create-test-accounts
```

必须使用 `WTG_PUBLIC_ORIGIN` 指定实际 HTTPS 测试部署，`WTG_REGISTRATION_REPORT` 可指定报告文件。默认报告写入被 git 忽略的 `.local/registration-report.json`，只记录检查结果及测试账号标识，不记录密码或令牌。

脚本验证真实注册表单、弱密码、确认密码、非法邮箱、用户名长度、重复用户名/邮箱、注册自动登录、用户名与邮箱登录、双向 SSO、新用户 API 准入、行程/账本/快照读写与跨账号隔离，以及匿名/错误受众和管理路由拒绝访问。它通过 HTTPS 提交真实身份表单，**不等于浏览器像素排版或点击渲染验收**。

测试后应通过 SSH 的 Keycloak 内部管理接口，仅删除报告中 `qa-reg-...` 前缀且精确匹配本次 runId 的测试账号；两个业务库按对应 issuer + subject 删除这些测试用户的数据。先确认匹配对象，勿按模糊前缀删除其他账号。业务库没有跨库自动级联删除身份用户；不能仅删除 Keycloak 用户就认为业务测试数据已经清理。
