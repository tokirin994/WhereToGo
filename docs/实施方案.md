# TravelAtlas 项目实施方案

## 1. 项目目标

TravelAtlas 是一套地图优先的个人旅行地点管理与行程规划 Web App。地点收藏、地点分类、地图展示、手动编辑和行程持久化不依赖大模型；大模型只负责在用户主动请求时安排已有地点的游玩顺序、日期和时间。每份行程由同一份结构化数据驱动编辑器、网页预览和独立 HTML 导出。

首版按可验证的阶段交付，不把尚未接入的外部服务伪装成真实能力。没有地图 Key 或模型 Token 时，地点管理、演示地图、手动行程和导出仍应可用。需要实时地图、地理编码、路线、天气或模型规划时，界面明确显示服务未配置或数据来源。

## 2. 参考资料与边界

- `one-click-travel-skill` 的 README、SKILL.md、`references/data-schema.md` 及 HTML 模板说明了结构化路线点、地图优先攻略和独立 HTML 的实现方向。项目没有发现 LICENSE 文件，因此只借鉴公开描述的产品思路和数据概念，不复制其源码、模板或素材。
- `pitravel.cn` 在当前环境请求返回代理 403，无法核验其页面内容；实现不依赖该站的私有内容。
- 链接解析遵守目标网站服务条款与访问控制。不绕过登录、验证码或反爬限制；URL 抓取先完成 SSRF 防护。无法读取时提供粘贴正文、手动录入和用户确认流程。
- 景点价格、评分、开放时间、天气和路线耗时只在有可验证来源时展示；未知值保持为空或标记“待确认”。

## 3. 技术与运行架构

采用前后端分离的模块化单体与 Monorepo：

| 部分 | 技术方案 | 职责 |
| --- | --- | --- |
| `frontend/` | Vue 3、TypeScript、Vite、Pinia、Vue Router、Element Plus、Tailwind CSS | 地图首页、地点库、合集、导入确认、行程编辑、预览和设置 |
| `backend/` | Java 21、Spring Boot 3、Spring Web/Validation/Security、MyBatis、Springdoc | REST API、领域规则、外部 Provider、密钥处理与导出 |
| 数据库 | PostgreSQL + PostGIS、Flyway | 持久化地点、来源、合集、行程、路线和备忘录；空间索引支持地图范围查询 |
| 本地运行 | Docker Compose | PostgreSQL/PostGIS；Redis 仅在确有异步任务需求后加入 |
| 文件与导出 | 本地隔离目录、Provider 接口预留 MinIO/S3 | 图片、导出 HTML；导出页可独立打开 |

地图、地理编码、路线、天气、网页解析、LLM 和导出都通过 Provider 接口接入。国内默认适配高德，后续可以增加其他实现。坐标值必须带坐标系和可信状态，不能混用 WGS-84 与 GCJ-02。

## 4. 模块与核心数据

### 4.1 后端模块

- `places`：地点、分类、标签、来源及坐标可信状态。
- `collections`：用户地点合集与合集地点排序。
- `imports`：导入任务、解析器适配器、候选地点和人工确认。
- `maps`：地点搜索、地理编码、视窗查询、路线与距离 Provider。
- `trips`：行程、每日计划、停靠点和路线段。
- `planning`：LLM 配置、结构化输入、JSON Schema 校验、约束检查与重新规划。
- `exports`：预览 DTO、独立 HTML 渲染、导出文件。
- `notes`：可关联地点或行程的备忘录。
- `common` / `security` / `infrastructure`：统一错误、审计字段、权限、文件和外部服务客户端。

### 4.2 首批数据库实体

首批迁移围绕 `users`、`places`、`place_categories`、`tags`、`place_tags`、`source_links`、`place_sources`、`place_collections`、`collection_places`、`import_jobs`、`trips`、`trip_days`、`trip_stops`、`route_legs`、`trip_notes`、`llm_provider_configs`、`export_artifacts`、`share_links` 设计。

地点与行程分离：删除行程不能删除收藏地点；地点来源允许多对多；行程停靠点引用地点并保存必要的历史快照。表包含稳定主键、`user_id`、时间戳、软删除字段、外键和适当索引；地点坐标使用 PostGIS 空间类型与空间索引。

### 4.3 前端主页面

桌面端为左侧地点与筛选、中间地图、右侧行程面板；移动端为地图、底部抽屉和浮动操作。地点列表与地图标记双向联动，未确认坐标的地点只进入“待定位”列表。首页不是营销落地页或聊天界面。

## 5. 分阶段交付

| 阶段 | 交付范围 | 完成标准 |
| --- | --- | --- |
| 0. 基础结构 | Monorepo、忽略规则、README、环境变量示例、架构/数据文档、前后端/数据库启动骨架 | 新环境能按文档安装并启动；密钥不进入仓库 |
| 1. 可预览 UI | 地图优先首页、导航、演示地点卡片、分类侧栏、行程侧栏、响应式布局、演示地图 | 浏览器可访问并交互；演示数据显式标识；无地图 Key 时仍有清晰地图占位和地点操作 |
| 2. 地点闭环 | CRUD、分类/标签、合集、地理编码 Provider、地图视窗查询、持久化 | 手动创建地点后可查、改、筛选、刷新恢复；未知坐标不伪造 |
| 3. 链接导入 | URL 安全检查、通用 HTML/元数据解析、规则抽取、地点候选、去重、人工确认、批量任务 | 公开网页可导入或给出明确失败原因；登录墙和被拒访问有手动补录路径 |
| 4. AI 规划 | OpenAI-compatible Provider、后端加密配置、测试连接、行程约束、结构化模型输出与校验 | 无 Token 可手动规划；有配置时模型只能选择后端提供的 POI ID，冲突可解释 |
| 5. 编辑、预览与导出 | 每日时间轴、拖拽排序、路线 Provider、`/trips/{id}/preview`、独立 HTML 导出 | 一份持久化结构驱动编辑、预览、导出；重新导出不调用模型；地图失效仍能读行程 |
| 6. 备忘录与分享 | 备忘录 CRUD、地点/行程关联、只读分享基础、模块扩展接口 | 独立模块权限清晰；分享凭证与模型密钥完全分离 |

每阶段先跑对应验证，再开始下一阶段。第一阶段使用 Mock 数据，但在 API 边界预留替换点；不把 Mock 响应描述成真实后端集成。

## 6. API 与数据契约

API 统一前缀为 `/api/v1`，统一分页、响应、错误码和参数校验。先定义 `places`、`collections`、`imports`、`trips`、`maps`、`settings/llm`、`notes` 的资源契约，并通过 Springdoc 发布 OpenAPI。

行程导出使用独立 `TravelExportDTO`，承载 `trip`、`attractions`、`hotels`、`transit`、`routes`、`sources`、`map`、`weather`、`foods` 和 `notes`。路线段和停靠点必须是结构化字段；`poiId` 必须来自数据库候选集合。在线预览与 HTML 文件共用同一 DTO 与转换逻辑。

## 7. 安全、隐私与可靠性

- 外链导入防 SSRF：只允许受控 HTTP(S)，解析并验证 DNS/IP，阻止 loopback、内网、链路本地和云元数据地址；每次重定向重新校验，限制重定向数、体积、MIME 类型和耗时。
- HTML、用户备注和模型结果均作为不可信输入处理；做输出转义/安全渲染，绝不执行模型生成的代码、SQL 或任意 URL。
- LLM 密钥仅由后端加密存储和调用；不写入日志、LocalStorage、导出文件或示例配置。前端只展示配置状态和脱敏标识。
- 文件上传校验类型与大小并隔离存储；所有外部请求设置超时、受控重试和必要的限流。
- 使用软删除、幂等导入、数据库约束和事务保护业务数据；不因删除行程级联删除地点。

## 8. 验收与质量门槛

1. 无 AI Token：启动系统、手动新增/编辑地点、放入合集、创建手动行程、刷新后数据仍存在。
2. 地图：已定位地点可筛选并显示；未定位地点不出现在虚假坐标上；列表与标记选择互相联动。
3. 导入：公开页面可形成候选卡片并由用户确认；不可访问页面显示原因并可粘贴正文继续；重复地点有确认/合并流程。
4. 规划：模型输出通过 Schema、POI、营业时间、时间冲突与硬约束校验；失败可恢复并说明原因。
5. 导出：预览与独立 HTML 内容一致；HTML 无服务端密钥；地图资源不可用时仍可查看文本行程；导出已有行程不需要再次调用模型。
6. 工程检查：前端构建与类型检查、后端测试和打包、数据库迁移、关键 API/端到端场景按阶段运行；记录通过、失败、跳过和未执行项。
